# 原理图评审工作台设计规范

## 使用场景

面向硬件工程师的工程评审与复核工具。优先展示当前项目、材料版本、明确的运行范围，以及与原图和来源绑定的结论。设计服务于「材料准备 → 检查执行 → 证据复核」，不使用营销首页或虚构统计。

## Skill 依据与取舍

使用 `ui-ux-pro-max` 的 `analytics dashboard --design-system --density 8 --variance 4 --motion 2`、`data dense dashboard --domain style`、`data dashboard --domain color`，命中 Data-Dense Dashboard；Vue 检索采用原生语义控件与动态 ARIA。自动输出的 Enterprise Gateway 营销布局与本系统不符，未采用。导航沿用真实评审流程，配色以冷灰蓝工作区为底，保留产品已有的 teal 主操作色；不引入图表、字体或动效依赖。

使用本机中文无衬线字体；位号、版本与功耗数值使用等宽或等宽数字。正文与辅助文字保持明确层级，不用弱对比小字承载状态。状态同时显示文字，颜色不单独承担语义。

## 页面结构

- 桌面固定左侧导航 208px，报告页默认收为 72px；顶部项目选择栏 60px。手机使用有文字的五项底部导航，并预留安全区域。
- 项目页先展示真实项目概况与项目入口，存储路径和流程说明下沉；搜索、空态和新建项目均保持可用。
- 材料页区分必要材料与补充材料，区分已导入和已检查；每次异步响应绑定原项目与请求代次。
- 运行页始终明确模式、规则、对象与模型。报告重建展示实际三阶段和零模型请求，不标成新的深审。
- 模型页区分连接、凭据与预算；未保存的修改不能沿用已保存配置的测试通过状态，保存时锁定整表。
- 评审页优先显示对象结论和限额；桌面三栏，中屏图纸与分析并排，手机切换问题 / 原理图 / 分析。正文只保留一份「分析思路」，证据和人工复核可直接定位。

## 交互与验收

- 原生按钮、输入和链接；图标使用一致 SVG，装饰图标从辅助技术树隐藏。键盘焦点清晰，手机主要操作目标至少 44px。
- 保留真实空态、错误、未配置和待确认；不更改机器结论、证据、图源或正式评审文件。
- 移动输入字号至少 16px；页面无横向溢出，长表格允许自身横向滚动，关键操作不逐字挤压。
- 滚动面板使用 `min-height: 0` 和明确定位上下文；隐藏标签不扩大文档。底部导航与固定工具条不遮挡内容或焦点。
- 动画只用于轻量状态反馈，遵守 `prefers-reduced-motion`。不添加自动轮播或阻塞内容的入场动画。
- 验证 1440 / 1280 / 1024 / 390px，真实 PDF 完绘、来源、深链和刷新；用受控 API 延迟复验跨项目响应，不向正式系统发测试写请求或调用模型。
