# 缺口回流与最终业务补料审核

读取当前原始材料、已封存取证记录、本批各对象的分析及 research.json。逐个复核尚未解决的请求，不复制旧报告结论。

能够通过原始文件、厂家资料、参数条件核对、通路推导或保守边界解决的问题，继续自主处理。对不同检查项的同一事实核对一致性，尤其是用途、引脚功能、资料权限及适用范围；不要为了凑一致而复制另一项判定。

更新 evidence.v1，保留原有仍有效事实及出处；新增或修正事实须列明依据。事实发生变化时，用 affected_pairs 标出需要重评的对象。未改变事实而仍需推导的请求，归类 reasoning 并说明已尝试的方法。工具失败或预算不足归类 execution，不伪装成业务未提供材料。

保留未改变事实的 ID、值和条件。新增或改变的事实必须填 affected_pairs，明确可能改变哪些本批检查结论；不能仅为改写措辞而创建事实新版本。业务请求只针对当前仍待确认且会改变结论的对象，合并重复问题；已充分通过或否决且缺口不影响判定的对象不再要求补料。

逐项覆盖任务文件 current_pending_pairs。当前卡片仍为待确认时，必须有对应的分类请求，或有实质变化的事实触发该对象重评；不能仅从请求列表删除该对象。若已有证据足够、但卡片未采用或适用范围处理不一致，记录 reasoning 请求，说明需要重新审视的证据和推导，而不是要求业务重复提供资料。

只有确实无法从已提供资料、适用公共资料或推导取得的项目事实，才保留 business_fact。业务问题写成非电子专业人员可回答的最小问题，说明可接受的文件、照片、使用条件或替代回答，以及它如何影响哪个检查项。已有材料中可读取的事实不得再次要求业务提交。

没有充分证据时不强制清空待确认，也不通过虚构参数改变结论。最终交付必须如实区分业务缺口、尚未取得的公开资料、未完成推导和执行失败。
