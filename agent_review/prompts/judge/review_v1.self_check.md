# 统一契约分析自检

本轮重读并修订分析稿，不写最终 JSON。完成一次材料与计算核对后结束；完整审计留在分析稿，缺口明确记录。

1. 从网表重新枚举影响决定性节点的所有引脚及直流负载，检查封装极性、支路电流、回流与状态相容性。图的每个分支必须来自同一状态；并联不串接。
2. 检查要求范围与已分析范围。不能把未分析的必需周期、负载或控制状态删成豁免；查明哪些改变极值或结论。
3. 核对对象端压、电流和耗散，保持同一工况参数与 SI 单位，复算电阻关系、串并联和节点平衡。
4. 搜索最严苛路径及控制端点，用比较、方程或单调性解释。若候选不可比，写明原因，不以数字大小替代比较。
5. 真实工作工况与放宽模型边界分别审计。若边界计算点不满足接口工作范围，是否仍能通过有效放宽与单调性覆盖真实范围？不能证明则不得用该边界判否；不能称其为已确认可达工作点。
6. 将主展示候选、充分判定依据和已确认全局极值分开；未确认全局最大值仍可有独立判定，但不能用任意外部假设作为充分证据。
7. 对每个缺口解释影响：仅极值、仅精度、或可能改变判定。后者写出有据可查的反向情形。缓存厂商、测试条件与典型参数要保留限定，不能凭空假设健康器件失效或换规格。
8. 为落卡准备唯一主状态、必要对照、至多四项核心输入、三条核心前提、三步推理。完整模型、审计和证据保留，不把长分析复制进业务区域。
9. 业务文案必须还原为材料中的真实网名、位号或明确中文节点描述；分析为列式临时定义的节点字母不能直接带进标题、比较理由、前提和判定说明。

展示自检：reasoning_steps 只描述分析与求解顺序，不含具体物理量数值、限额和最终判定；将这些数据保留在计算与结论字段。

对象思路自检：reasoning_steps 每条是否说明本对象已确认的具体连接/器件状态及其应力影响？是否有实际位号或网名、因果关系而非“核对—求解—比较”的通用流程？泛化空话必须回到材料重写。不要靠删去数值就把计算结论当作思路。工况标题应能直接读懂接口/器件状态，待证等级放标签。

统一分析自检：本批采用 analysis.v1 时，分析思路须把对象的具体事实、条件和因果关系融合在至多三步中，不分列前提与思路；关键假设仍有稳定 ID、状态和真实来源，分析引用有效。未确认条件和模型假设不得被改写成确定事实，不把具体计算结果堆进分析思路。旧 reasoning_steps/assumptions 不与新字段重复输出。
