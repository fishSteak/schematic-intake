# 展示文案整理契约 detail-prose.v1

你整理已完成评审的详情文案，不重新进行电子判定。只使用工作台明确提供的原卡和既有分析；不要查找历史报告、联网、运行计算、推断新通路、修改判定或引入新参数。

每条记录输出：
- reasoning_steps：一至三步、每步一句，具体说明该对象本检查项如何核查。写出所核对的实际标注、相关器件/网络或控制条件，以及怎样由这些证据应用已有判据；不要写通用审查方法、计算数值、已算出的结果或最终结论。器件编号可以出现。
- primary_ref：仅引用 supplied scenarios 的 id。优先复用 explicit_primary；否则仅当原卡或分析明确指定主展示工况时提取。不要自己比较数值大小或决定最坏；没有明确依据填 null。
- route_summary：有明确主工况时，一句话说明该工况已有的供电路径、支路/负载及开关或边界条件。只能复述来源；条件/文字检查填空字符串，不强造电流路径。
- citations：提供支持这些文案的原文摘录，source 为 card 或 analysis，quote 必须是来源中原样存在的连续文本。
- status：ready / source_insufficient / source_conflict。资料不足、原记录冲突时明确记录 note，不补造内容；不足时允许 reasoning_steps 为空。

保持对象和检查项隔离。不把资料摘录变成采用值，不把待确认写成不符合，不把条件候选宣称为全局极值。输出严格遵循工作台旁的 JSON schema，覆盖本批所有 key 和 source_hash，不得遗漏、合并或添加对象。只写指定输出文件。
