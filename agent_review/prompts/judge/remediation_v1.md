# 外层整改建议 remediation.v1

你为当前对象生成可以执行的外层整改建议，依据工作台中已通过校验的 review_card、判据、材料输入、模型计算、整改措施及证据限定。它们是本阶段的输入，不重新进行电路评审，不修改原始材料或评审卡。

先读指定 .context.json 和 .schema.json，只向指定输出路径写一个 JSON。target、review_source_hash、schema_version 复制工作台；不得读历史报告、docs、样例或其他对象的结论。

summary 使用中文，1～2句话，包含以下内容：
- 具体动作：明确保留或调整什么参数、采用什么整改路线，以及必要的封装/焊盘调整，不能只写“评估、补资料、重算”。
- 参考规格：从当前对象的实际物料参数、候选应力和判据使用比例推导最低需求，给出待验证的参考规格。禁止预设位号、阻值、功率或预期答案；不得在没有来源时指定替代料号、封装型号或保证值。
- 验收条件：说明在哪类实际工况下测量/核算什么，以及满足什么可检验的要求，包括适用的温度降额和电路功能。

reference_spec 保留可追溯的输入引用、依据工况、最低额定需求、建议额定规格及限定条件。功率检查中，最低额定需求由所选工况耗散除以“当前功耗限额/材料额定功率”的使用比例推导；这只是该工况的需求，不得冒充已闭合的全局最坏需求。建议规格是整改验证起点，不能表述为保证合格。

候选工况带未证实条件时，summary 和 qualification 必须明确这是按当前候选得到的参考方案，最终须在真实最坏持续工况及温度条件下验收。材料不足以给出规格时，最低/建议额定保持 null，给出具体测量动作和明确的验收依据，不制造数字。

specific_action 和 acceptance_criteria 分别记录动作和验收条件；summary 应将这些内容及必要规格压缩到两句内。不要直接拼接全部 actions，不堆砌全部缺口，不使用“减载边界”等内部推理术语，也不复述长篇计算或正式判定。

写盘前自检：每个引用可解析，计算与输入一致，建议规格不低于本次参考工况的最低需求；summary 同时有具体动作、参考规格和验收要求，且限定条件没有被压缩掉。只生成本对象的建议，不修改已有 review_card。
