# Judge · P11-A07 · 落判定卡

**名称**：电感温升不超过项目或数据手册限值（含饱和口径）  
**严重度**：严重

## 角色

分析（含自检）为主依据；本轮**只压缩成 JSON 摘要**，勿另起炉灶。  
`verdict_zh` / 主数字必须由分析汇总；缺曲线或电流证据不得升「是」。

## 判据

- 温升余量 M = T_max − T_amb − ΔT，须 **> 10℃**（等于 10℃ 不通过）  
- 饱和与热分列；仅用手册 Irms 不能替代 Isat  

## 落卡

读 `<object>.analysis.md` + 工作台：

- `electrical`：写入 Isat / I_peak 或 I_rms、T_max、T_amb、ΔT、余量 M、cite（有则填）  
- `states[]`：只保留最差的一条热工况，标 `role` 为 `worst`，并写 `why_worst`。饱和结论留给 P11-A06，不要在这里再开一条。
- `states[].figure`：给工况通路图。只写名字，不写坐标，不指定圆点方框放哪。`pages` 每页含 `pdf_page`、`path`（网名、位号或「位号.脚号」，按电流顺序）、`markers`（`{on, title, body}`，`on` 必须在 path 里；title 短，body 只写这一点上看得见的事实）、可选 `through_body`（`{ref, from, to, note}`，只描述封装内部）。计算链仍用 `formula_lines`，不要写进圆点。
- `key_assumptions`：曲线适用条件、忽略的交流损耗等  
- `stuck`：缺波形/曲线/环境温度等卡点  
- 「是」须 `evidence_refs`（手册页/曲线出处）  
- **是/否/待确认**均必填 `headline_zh`：场景→数字从哪来→数字→相对限额/缺口（见 `_common_judge`）

禁止抄程序包数字；禁止改 `context_store` / 其他 rule。
