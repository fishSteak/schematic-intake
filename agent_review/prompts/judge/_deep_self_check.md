# 深审 · 分析自检（同会话）

重新阅读你刚写的 `.analysis.md`，只修订分析正文（不要写 JSON）。不要点名任何具体器件类型，不要为显得完整而堆工况。

## 停手标准

以「还有没有没写透的通路 / 手册依据 / 闭合前提」为准；**不要**以「能不能交 JSON」为准。

按下面**通用**问题过一遍；有问题就改正文。

1. **自相矛盾 / 假稳态**：有没有把站不住或证据不足的态当成已证明？
2. **主依据是否闭合**：决定过/不过的那一档，是否写清了电位/电流（或供电脚→轨）如何落到对象上？
3. **手册口径**：额定/推荐范围/曲线/Isat 等是否写清出处与适用条件？有没有把绝对最大当正常工作点？
4. **取舍是否可见**：未计入包络的边界是否写明原因？
5. **卡点 ↔ 置信度**：缺证据是否反映为待确认/降置信，而不是猜数字升绿？
6. **落卡预备（是/否/待确认）**：分析里是否已能压成一句 `headline_zh`（场景→数字从哪来→数字→限额/缺口）？缺数源就补写，勿留「最坏约 xV」而无出处；勿用长 summary 顶替。
7. **工况写法**：本项若不产出工况，分析里就不要列应力态。本项若要求分列子结果，不要收成一条最差。其余应力项是否只留了最差的一条，并把较低档写进说明？通路上的网名和位号是否写清，供落卡画图？式子是否只用材料里已有的网名和位号？每个数是否写清从哪来？

无问题 → 文末可写「自检：未发现上述问题」。

统一分析自检：本批采用 analysis.v1 时，分析思路须把对象的具体事实、条件和因果关系融合在至多三步中，不分列前提与思路；关键假设仍有稳定 ID、状态和真实来源，分析引用有效。未确认条件和模型假设不得被改写成确定事实，不把具体计算结果堆进分析思路。旧 reasoning_steps/assumptions 不与新字段重复输出。
