## 1. 目标形态（已对齐的产品口径）

| 项 | 约定 |
|---|---|

## 1.1 C5 标准（后续检查项都按这个出图）

新对象只新增通路规格（折点、裁切、圈注、一句结论），然后调用现有 `stress_path_render`。禁止另写绘图脚本，禁止手改 PNG。

### 连线

- 折点落在原理图绿网上，并**穿过本工况的器件本体**再接到下一网（C5：`N_LED_G` 横线向下穿过 R2，再向右进 `POW_TECH`）。
- 入脚对到正确管脚的红脚，不跟旁边贴得很近的网标走（C5：VCC 进 pin2 COM，不进 pin1 A）。
- 封装内部只画虚线，走本体里面；禁止沿脚列把多脚串成一条实线。
- 禁止为了「看起来顺」穿过旁边的电源轨或别的网。
- 跨页用同一个网名接力。
- 小圆点落在器件或端口符号上，不用大圈。

### 文案

只写这条工况上看得见的事实：器件名、数值、接到哪里。被测器件上直接写判据数字（C5：两端 15.1V，限额 12.5V，超过限额）。

不写：

- 本工况没走的脚、电阻、网（「不经 R29」「不走 pin1」）
- 图面几何说明（「旁边 VCC 只是交叉」）
- 绕的过程话（「释放后才」「不再被拉低」「此点」）

每步页眉一行结论；完整计算公式留在报告里，不铺进原理图。

### 清晰度

补充文字（页眉、圈注、封装内说明）按最终像素直接画，不再先画大再缩小。样式色、线宽、卡片以渲染器里的 token 为准，不在规格里另配一套。

## 2. 前面画图出现的问题（按类归档）

### 2.1 拓扑画错（最严重）

| # | 现象 | 根因 | 纠偏 |
|---|---|---|---|
| A | LED1 脚列被竖线「串短」 | 用一条连续折线/桥接竖穿 A/COM/C/D/B | **拆成两段外铜线**；封装内 COM→G 用虚线 `via` 走**本体内侧**，禁止脚列直连 |
| B | 第 5 页竖线穿过 U2 旁 **VCC24V** | 为「拉长源头」在 `x=474.8` **凭空加竖段**，绿网上无此铜线 | 折点必须来自绿网：`POW_TECH` 沿 **x=428** 下落再水平进开漏节点 |
| C | 看起来像和 R29 串联 | 脚列竖穿 + 文案写「并列」但视觉像共线 | 电气上 R2∈`N_LED_G`，R29∈另一段选网，**并联不同段**；画法不得制造共线假象 |
| C2 | VCC 源头横线像走了 `N_LED_D`/R29 | `N_LED_D` 网标紧贴 VCC 水平线；源头折线又拉满整列电阻 | **电气跟 VCC→COM 是对的**；视觉上源头段只画到 VCC 标附近入 COM，勿横穿 R29 列 |
| C3 | 高亮不像从 VCC 进 COM | 把 **pin1 A** 的 y=244.4 水平线当成 VCC（网标贴得近）；真正 COM 是 **y=251.6**，左侧有 VCC 电源符(红 T) | **VCC→COM**：`(521.6,251.6)→…→(550.4,251.6)`；**禁止**再画 y=244.4（那是 A/N_LED_A） |

**硬规则：高亮折点 ⊆ 原理图绿网（或显式声明的封装内虚线路径）。禁止「看起来顺眼」的几何捷径。**

## 3. 推荐架构：不要只靠 Prompt 画图

### 3.1 一致性口径（按你的真实诉求）

**要对齐的是「风格 / 样式 / 连线画法习惯」，不是和某张原型图像素级一模一样。**

| 维度 | 要稳定（像你看过的原型） | 允许按对象变化 |
|---|---|---|
| 视觉 | 青蓝半透明高亮、卡片页眉、编号圈注、故事板/判定条、禁止用红 | — |
| 画法习惯 | 贴绿网折线、封装内虚线桥、图幅含邻路、源头起算、跨页接力 | — |
| 内容 | — | 不同对象的通路、折点、跨页、圈注文案、判定结论 |

你的担心成立：**若只靠 Prompt 让 SDK「自己画一张图」，样式很容易跑偏**（线色、卡片、标注形态每轮都不一样）。  
正确做法是把「你已认可的原型风格」**冻进渲染器**；SDK 最多生成「这条对象怎么走」的数据，再调用同一渲染器出图。

### 3.2 结论（直接回答）

**最终量产出图：不是「每次给 SDK 一段自然语言让它现画 PNG」。**  
应拆成两层：

```
┌─────────────────────────────────────────────────────────┐
│  A. 风格冻结的出图器（程序）                               │
│     agent_review/stress_path_render.py                  │
│     · UI token：色、线宽、透明度、卡片、圈注、故事板        │
│     · 画法规则：贴网 / 封装内虚线 / crop 含邻路            │
│     → 保证「看起来还是那种图」                             │
└─────────────────────────────────────────────────────────┘
                          ▲
                          │ 只写入「这条通路怎么走」
┌─────────────────────────────────────────────────────────┐
│  B. Cursor SDK Agent（可选）                              │
│     读原理图 PDF / KG / program_stress                   │
│     产出或修订通路规格（折点、markers、crop…）             │
│     → 不同对象连线/描述不同是正常的                        │
│     禁止自创一套画风或直接手绘 PNG                         │
└─────────────────────────────────────────────────────────┘
```

| 问题 | 答案 |
|---|---|
| 只给 Prompt 能不能稳住风格？ | **很难。** Prompt 管不住像素级视觉；风格必须由渲染器代码保证。 |
| 连线可不可以不同？ | **可以、应该不同。** 对象变 → 规格变 → 通路变；只要仍走同一套画法规则。 |
| 如何保证 SDK 跑出来不像另一套产品？ | SDK **不得另写绘图逻辑**；只填规格 + 调用 `stress_path_render`。样式要改，改渲染器一处，全对象一起变。 |

### 3.3 两锚点就够（风格 + 通路数据）

1. **风格锚点（冻结）**：`stress_path_render.py` 里的 UI token + 绘制函数。你现在认可的 C5/C9 原型，本质上是这份代码的输出；以后批跑都走它，风格就不会「换皮」。  
2. **通路规格**由工况上的 `figure` 提供名字和文案，`stress_figures` 贴到绿线后再交给渲染器。不按位号在代码里保存折点。  
   - `pts` / `polylines`（PDF 点，贴绿网）  
   - `bridge_note.via`（封装内，禁止脚列）  
   - `crop_box`（含邻路）  
   - `markers`（文案与位置）  
   - `label` / 跨页 `continue_to`  

可选加强：留 1～2 张「风格金样」只做人眼对照或粗检（有没有深蓝旧顶栏、有没有红高亮），**不要求**和新对象图叠加对齐。

### 3.4 SDK 任务该怎么写（推荐分工）

**批跑出图（风格稳定）——程序任务，Prompt 极短：**

```text
运行：python -m agent_review.stress_path_render --board <板> --objects <列表>
禁止修改渲染器样式 token；禁止另写绘图脚本。
```

**为新对象补通路规格（连线可变）——SDK Agent：**

```text
目标：为对象 Cx 生成/修订 stress path 规格，供现有 stress_path_render 使用。
风格：不得自创；色/线宽/卡片/圈注形态以渲染器为准（对照已认可的 C5/C9 产物观感即可）。
内容：本对象通路、折点、圈注文案按拓扑自行填写（与 C5/C9 连线不同是正常的）。
硬约束：
1. 折点落在绿网上；禁止竖穿多脚/电源轨的几何捷径。
2. 封装内只用 bridge via + 文案，走本体内侧。
3. crop_box 含影响判定的邻路。
4. 只改规格，然后调用渲染器出图；禁止手动画 PNG / 另起绘图代码。
5. 对照 docs/工况通路图-踩坑与一致性归档.md §2 自检。
```

要点：**Prompt 负责「这条怎么走」；渲染器负责「画出来长什么样」。**

### 3.4 和现有混合评审的关系

- Agent 深审（Judge / `Agent.create`）继续写分析卡与 verdict；**工况图是旁路可视化**。  
- `program_stress` JSON 提供应力结论与拓扑线索；通路折点目前仍需人/Agent 按绿网落点（尚未全自动追线）。  
- 日后自动化追线成熟后：Agent/程序写 `*.path.json` → 同一渲染器出图；Prompt 仍不应直接负责像素。

## 4. 自检清单（每次改图/改规格必过）

- [ ] 折点是否逐步对齐绿网？（无空中飞线、无穿 VCC/脚列）  
- [ ] 封装内是否虚线 + 文案，且 `via` 在本体内侧？  
- [ ] 邻路是否进 `crop_box`？  
- [ ] 圈注文案是否区分「并联段选」与「本工况串联电阻」？  
- [ ] 跨页是否同网名接力、箭头方向完整？  
- [ ] 线色非红；线宽/透明度未走极端？  
- [ ] 是否只改了规格/渲染器并重跑命令，而非手改 PNG？  
- [ ] （若有金样）与金样差异是否可解释且已更新金样？

## 2026-10-21：主工况与整图裁剪修复

- 详情与出图曾使用两套主工况优先级：一端先选 worst，另一端先选 worst_candidate，造成已经生成的候选图在详情中消失。现在共用 presentation.primary_state_index：唯一 primary → 唯一条件极值候选 → 唯一确认极值；多项无明确标签不按数字猜选。已有局部静置 worst 不覆盖明确的更重条件候选。相应说明由模型按当前选中引用重新整理，不改原判定卡。
- 精确连线分支曾只按通路节点计算局部 crop，现所有渲染分支统一按整页电路线和邻近标注范围裁剪，排除图框、标题栏与品牌信息；无可靠电路特征时保守保留整页。水平/竖直线段的 PDF Rect 面积为零，不能用 Rect union 累加范围，须用坐标极值累加，否则会只剩局部封装。
- 同一周期的充放电相位不是两项独立最坏工况；相位与跨页各自具名，预览显示来自同一主工况。图注读取模型通路说明，页级 route_summary 优先；几何诊断保留在元数据，图片只展示中文定位提示，不把英文技术日志充当工况说明。未解方向继续不画箭头。
- 出图缓存含渲染器、规格生成器和实际图注文案指纹，修裁剪或图注不会复用旧图；连续大图生成后关闭 PDF/图片资源并回收内存。
- 详情中的工况标题与通路说明不重复堆叠，已有说明时仅保留一份主说明；对象摘要与核心工况使用一致层级及轻量强调。
- 规格书摘录须按精确料号跨检查项复用，不能只为某些功耗/电容检查补齐。公共展示补齐仅添加来源摘录，不覆盖本次评审采用值。P11-A02 的空摘录曾由展示补齐范围遗漏造成，并非 PDF 不存在。
