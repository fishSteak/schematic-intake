# L1 电平兼容独立复核（P12-A02 / P21-A01，2026-10-22）

## 结论

两项均适用，L1是LM392-N比较器的开集电极输出到MC14584B数字施密特输入的网络，**不是电感、不是运放模拟输出**。

- **P12-A02：不通过。** 低电平供吸能力有充分余量；高电平仅通过LED1+A段及R33=200kΩ从VCC24V上拉，没有到+12V的合法高电平电源或外部钳位。释放高态依赖U6输入保护结构吸收注入，无法保证L1在U6推荐输入范围0～12V内。这个拓扑问题已闭合，不需要先补结构化层参数。
- **P21-A01：不通过（高电平不在接收器有效输入范围）。** 正常高态可越过正向施密特阈值，正常低态也可低于负向阈值，故问题不是“VIH不够高”。但“超过VIH”不等于兼容：高电平的上界必须同时落入输入允许范围，当前24V上拉对12V接收器不满足。若本规则在实现中被严格限定为仅比较阈值大小、另有独立卡检查输入过压，则本项的阈值子结论应记“正常标称阈值兼容，12V全温逐点保证未提供”，同时将已证实的输入范围不兼容交相应卡；不能写成VOH不足或开集电极无VOH所以一概待确认。

没有证据证明U6一定立即损坏。R33使注入仅约数十µA，远低于±10mA绝对最大电流；这不把内部保护二极管变成厂家批准的正常电平转换器，也不证明输入电压必定≤VDD+0.5V。

## 独立推导

### 低态

SIG_ORI高于LEVEL1时，比较器输出晶体管导通，L1拉低。最坏把LED压降设为0、R33下偏1%：

`Ipull,max ≤24/198kΩ =121.2µA`。

再加U6最大输入漏电约1µA，仍约0.122mA，远小于LM392-N保证饱和电压所用4mA。正常单调输出特性下VOL≤0.7V是充足保守界；不能把6mA/16mA的典型吸电流当此处需求。

U6负向阈值表给5/10/15V供电，跨表最低VT−约1.5V；12V负向阈值正常在数伏。即便用最低1.5V的宽松工程包络，0.7V仍至少有0.8V余量。严格厂家12V逐点全温最小阈值未列，不能把插值得出的约3.6V写成保证值；但这不构成低态欠驱动的证据。

### 高态与推荐输入范围

SIG_ORI低于LEVEL1时，pin1开集电极关断，**不主动输出12V**。节点方程是：

`(24−VF_LED(I)−VL1)/200k = Ioff,U7(VL1)+Iin,U6(VL1)`。

如果要求正常VL1≤12V且不让保护结构导通，在VL1=12V时，按LED低电流VF≤其20mA上界2.4V的正常单调关系，提供的上拉电流至少约：

`(24−2.4−12)/202k =47.5µA`。

而U7关断漏电最大约1µA，U6正常输入漏电最大约1µA，总共仅约2µA。二者无法吸收47.5µA，上拉电流继续给输入电容充电，**12V不是平衡点，L1必然试图越过12V**。这比武断计算VOH=24−2=22V更严谨，也无需知道LED在50µA时的精确VF。

不考虑U6保护结构时，节点接近VCC24V，常见估计约22～24V，显然不在12V接收器正常输入范围，也高于绝对最大12.5V。实际U6有输入保护二极管，通常将节点钳在12V之上一个正向压降，形成约：

`Iinj ≈(24−VF_LED−12−VF_clamp)/200k ≈45～55µA`。

即使所有压降取0，注入总电流也≤121.2µA。不能从“电流小于10mA”推导“钳位压降≤0.5V”；厂家没给出这一路径的允许正常注入条件/钳位电压保证。因此绝对最大电压是否实际超过12.5V仍依赖该二极管I-V和电源吸收状态，但推荐范围违例已经确定。

### 阈值与功能辨析

U6在10V供电的VT+最大7.0V，15V最大10.6V；VT−在10V最小3.0V，15V最小4.5V（各温度列略有变化）。12V未列逐点保证，不能用典型VT+=约6.4V签全温保证。正常L1高态接近12V以上，即使以15V表的10.6V当宽松工程比较值，仍可越过正向阈值。低态≤0.7V则远低于负向阈值。由此功能上通常能翻转，高电平还可能被内部二极管“帮忙”钳住；这解释了电路可能看起来能工作，但不解决输入范围兼容。

L1的比较器输入是模拟量不影响其输出用于逻辑；U7另一单元pin7为运放输出SIG_ORI，与L1没有直接输出连接，不能将其模拟输出摆幅搬到L1。LED支路是实际非线性上拉，不是“没有上拉”，也不是纯200kΩ接+12V。

启动时，24V已起而+12V尚未建立，则U6可能经同一路径反向供电。R33将其限制在约0.12mA以下，但没有材料保证+12V轨的吸收能力、U6上电状态及钳位电压，故不能以正常高态能够识别来宣称全工况兼容。

## 已闭合与未解

已闭合：实际pin1→pin1、开集电极与施密特用途、实际24V/LED/200k上拉、低态负载数量级、正常高态越过12V的必然性、规则适用性，以及“不是VIH不足”的定位。

未解但不撤销上述不兼容：U6在12V供电、0～70℃的逐点保证阈值；输入保护二极管在约50µA时的准确压降；+12V轨吸收/断电反灌；完整时序频率和输入电容。前两者决定精确VOH/绝对最大余量，并不决定24V上拉是否在推荐输入范围内。建议修正为普通上拉至+12V、将LED指示与逻辑上拉分开，之后再核算上拉阻值、上升时间和全温阈值；本次不修改设计。

## 针对主稿待确认意见的再核查（第二轮）

本轮逐页复核准确onsemi MC14584B/D Rev10（PDF共10页，2025-10）正文第1～5页及所有脚注，结论如下：

1. 第1页MAXIMUM RATINGS同时列出输入/输出电压−0.5～VDD+0.5V和每脚输入/输出电流±10mA，电流条目没有“只要限流即可豁免电压范围”的脚注。唯一编号Note 1是封装功耗随温度降额，并非输入过压许可。
2. 第1页明确原文：**“For proper operation, Vin and Vout should be constrained to the range VSS ≤ (Vin or Vout) ≤ VDD.”** 这是正常运行范围要求；它与上方绝对最大表不同。
3. 第2页脚注是订货及停产说明；第3页脚注3～7分别涉及典型值不可作设计依据、典型动态电流公式、负载修正和迟滞定义；没有允许连续超过VDD但限流的例外。第4页典型应用是慢边沿整形和噪声抑制，不含24V到12V通过限流电阻的电平转换；第5页为修订记录。
4. 因此，在这一本准确型号手册中，**没有找到明确容许本电路连续高态接法的条款**。也没有从“Double Diode Protection”推断出禁止任何保护电流；它证明保护存在，不提供本接法的正常运行保证。

### 对“必须先知道LED微安压降”的回应

不需要精确值。假设L1仍在推荐范围顶端12V、所有输入保护都未参与，稳态漏电总和最多约2µA。若此时上拉电流要减小到2µA以下，200kΩ上的压降最多约0.4V，意味着单颗黄色LED正向压降必须至少约 **11.6V**。准确光华手册第2～3页20mA时VF最大仅2.4V；由正常LED正向I-V单调性，小于20mA的电流不可能靠正向VF升高到11.6V来阻断上拉。这是器件物理单调关系的工程推断，非把2.4V当微安点精确保证。LED低电流VF缺口会影响注入电流的若干µA，不能改变“输入电压试图高于12V、需保护结构吸收电流”这一结论。

更保守地，不使用2.4V精确上界，只要承认该单颗黄色LED在约50µA时VF<10V（极宽松工程界），在L1=12V时也仍有至少约10µA上拉，大于约2µA漏电。主稿若认为缺乏厂家微安曲线足以否定此推导，应明确其要求的是逐点保证证明，不能将通常半导体单调性与未知任意器件行为等同。

### 对“必须先知道12V保证阈值”的回应

要精确签发全温VOH/VT+裕量，确实需要12V阈值的保证包络或厂家确认；但**判断正常输入范围不兼容不需要VT+**。12V供电时正常输入上界就是12V，而高态方程在12V处尚有净充电电流。缺少12V阈值不会把这个已闭合的问题变回未知。

### 保护限流应用的边界及结论校正措辞

本轮额外检索到onsemi历史CMOS Logic Data DL131/D（2000）的厂家通用设计指南，第29页说明串联电阻可将可能引起闩锁的**电压瞬态**电流限制到10mA，从而作为保护方法。该指南同时要求输入/输出符合电压和电流最大额定，并强调供电时序；它没有给出本型号在连续正常高态注入约50µA时的逻辑功能、可靠性及12V供电吸收保证。旧指南可支持“限流显著降低损坏/闩锁风险”，不能直接代替准确型号正常范围。检索定位：https://www.z-tronics.com/documentation/datasheets/4000_4500-onsemi.pdf （厂家原始出版物的镜像，本轮未据其增加准确器件保证）。

故保留“正常推荐输入范围不兼容”的工程结论，**不升级成“必定超绝对最大”或“必损坏”**。P12-A02全工况兼容不能通过；P21-A01若卡契约包含接收器合法输入电平范围，同样不通过。若P21-A01契约仅检查阈值交越，不能拿输入范围问题伪装成阈值不足：应写“正常标称阈值交越充分；全温逐点保证尚缺”，并将范围问题独立呈现。这是规则分工，不是电路问题未闭合。

主稿“缺12V阈值、缺LED微安VF所以全部待确认”遗漏了推荐输入范围这一独立可审计依据，应至少增加已证实的24V非线性上拉对12V输入的持续保护注入问题。若后续取得明确适用于MC14584BDR2G的厂家连续注入许可，应据其限制重新判断，不能仅凭本次未找到许可宣称所有限流保护应用均不合规。
