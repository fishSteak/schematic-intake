# 单仓迁移（2026-10-20 记录，2026-10-22 更新运行说明）

`schematic-intake` 是原理图自动化评审的唯一开发仓。运行不再依赖同级 `schematic-review`，也不读取 `SCHEMATIC_REVIEW_ROOT`。历史资料位于本仓 `archive/schematic-review/`，仅用于回溯，后续仅修改本仓。

## 运行

新 clone 先安装 Python 依赖并构建前端。在仓库根目录执行以下 Windows PowerShell 命令，不需要激活虚拟环境：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm --prefix report_ui ci --ignore-scripts
npm --prefix report_ui run build
codex login status
```

依赖版本按 Python 3.12 / Windows x64 验证（见 `requirements.txt`）；其他 Python 版本需另行验证。后续命令中的 `py` 表示已安装项目依赖的 Python；采用上面的虚拟环境时，将其替换为 `.\.venv\Scripts\python.exe`。其他环境使用相应虚拟环境中的 `python`。

```powershell
# 材料准备，包含查参；不运行对象判定
py -m kernel.run --board boards/0918全量
py -m agent_review.run --board boards/0918全量
py -m agent_review.serve --board boards/0918全量
```

现行 Agent 后端是 `agent_review/codex_agent.mjs` 调用本机 Codex CLI，默认继承用户的 Codex 模型配置。Node.js 要求 >=24.0.0（以根目录 `package.json` 为准）；新环境须自行确认 Codex 登录状态。根目录和 `sdk/` 的 `dependencies` 均为空，不需要 Cursor SDK 登录态、Cursor API 密钥或额外的 Agent npm SDK；前端依赖仍通过上述 `npm ci` 安装。

`report_ui/dist` 不进入 Git，不能假设新 clone 已含可用前端。独立运行验证也依赖这份本地构建，请先完成 `npm --prefix report_ui run build`。

流程演练可使用 `--dry-run`，但它不是全链路离线保证：当前报告汇总阶段在缺少分析文案缓存时仍可能调用真实 Codex，使用网络及模型额度。应在测试板副本上演练，并先确认鉴权和额度；此模式也不能用于验证正式对象判定质量。

## Git 内容范围

只提交开发与可复现运行所需内容：源码、规则、测试、依赖清单/锁文件和文档；`.venv/`、`node_modules/`、`report_ui/dist/`、Python 缓存、大部分 `boards/*/review_out/` 及板级 `history/` 已忽略。

`boards/<板>/*.json` 是材料与评审配置；`boards/<板>/review_out/board_kg.json` 目前仍是离线验证和既有入口使用的知识图输入，保留现有忽略例外。`materials/` 保存原始输入，`migration_baseline/` 保存迁移/回归基准，供新环境准备材料与比较预期结果。不要将这些受控输入和可重新生成的报告、查询缓存一起排除。

## 开发目录

| 目录 | 职责 |
|---|---|
| `kernel/` | s0–s5 材料准备、程序检查器、工况与计算基础 |
| `solve_prog/` | 电路求解与现有回归测试 |
| `agent_review/` | 阶段机、密封上下文、Agent 编排、汇总与门禁 |
| `rules/` | 检查项清单、Agent 白名单与判据 |
| `report_ui/` | 现行报告前端，读取 review_out JSON |
| `vendor/expert_html/` | 本仓兼容 HTML 构建器及 PDF.js 资源 |
| `archive/schematic-review/` | 旧文档、OpenSpec、脚本与演示资料；不作为现行运行入口 |
| `migration_baseline/` | 迁移清单、旧实现结果及独立验证记录 |

同名实现以 intake 为准，没有用旧仓覆盖。旧检查器需要的独有模块已迁入；展示文案的额外过滤已补入现有 report_text。

当前检查项以 `rules/product_center_15.json` 为准，Agent 分流以 `rules/agent_rule_ids.json` 为准。历史文档中的项数、旧仓路径及全 Agent 方案仅供回溯。

板卡 `materials.json` 支持相对于板目录的材料路径。目前 0918 板引用仓库内 `materials/0918全量/`，不依赖旧仓材料或仓库外目录。

## 验证

```powershell
py scripts/verify_standalone.py
```

脚本复制运行代码和已构建的 `report_ui/dist` 到不含旧仓的临时目录，验证现有求解测试、CLI 入口、程序检查/P11/辅助通路与迁移基线一致、本地 HTML 构建及报告 HTTP 读取。成功结果保存在 `migration_baseline/verification.json`。脚本不修改正式对象卡，但其 `--dry-run` 流程仍可能启动真实 Codex 生成分析文案，不能视为纯离线验证。仅需本地代码检查时，运行单元测试和前端构建即可。

迁移基线通过与整板评审完成是两件事。现有板缺卡和无效卡需后续通过正常评审流程补齐。
