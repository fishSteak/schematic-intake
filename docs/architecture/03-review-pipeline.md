# 评审流水线

## 材料准备

[kernel/run.py](../../kernel/run.py) 的s0～s5依次接入材料、建连接图、找规格书、抽参数、索引PDF并建立板级知识图。板级 `materials.json` 指向原始材料；中间产物写入该板 `review_out`。身份、测试条件、原文页码和来源哈希与参数数值同样重要。

## 枚举与分流

`enumerate_stage` 枚举检查项和候选；`rule_modes` 区分程序检查和Agent检查，适用性结合实际用途与器件分类。缺参数不等于不适用。代表性批次由显式对象清单限定；未选对象不能统计为本轮已审。

## 对象工作台

`context_build` 和 `workbench` 将规则全文、对象连接、邻件、设计脚号/脚名、公共工况、规格书证据与契约组合到 `<对象>.context.json`。规则和公共参数应保持来源边界：公共直流默认值不能删除检查条款要求的正常周期模式。

## Agent任务

任务单位是“检查项＋对象”。`judge`声明任务，Node编排调用Codex CLI。delivery.v1首轮同时写分析、正式卡和研究记录；复杂项随后进行同会话决定性核查，有错误再定向修复。一般执行入口还保留历史的分析、自检、落卡阶段组织，不能混称为一套已完全清理的流程。

Agent可以自行读取和查证准确型号资料，遇到冲突需说明处理。原始事实与计算结论分开，独立工程师分析只作推导线索，不能注册成原厂事实。

## 保存和恢复

`finalize_card` 执行契约、证据等检查并附控制器运行信息；`delivery_progress` 记录当前对象的运行状态、判定、实际run_id和错误。执行签名包含材料、工作台、提示词/契约相关文件、模型/推理配置等因素。

材料和规则未变不意味着任意旧分析都可复用；恢复需核对对应签名及工作台。阶段快照保留分析和本对象新取得的附件。完成对象可独立保存，失败只修相关阶段。恢复校验不能伪造新模型运行。

## 图与报告

按明确主依据引用生成图；聚合对象卡，转换统一详情，写报告数据和两个HTML产物。HTML与Vue消费同一详情内容。代表性发布工具在发布前后检查来源、媒体、判定一致性和展示；失败回滚已发布交付文件，保留真实分析与诊断。

## 三种完成状态

| 状态 | 含义 |
|---|---|
| 运行完成 | CLI返回，文件已保存，运行信息可追溯 |
| 契约完成 | 字段、引用、状态与部分一致性规则通过 |
| 电气判定完成 | 适用范围内有充分通过界或超限依据；确缺业务事实时明确限定 |

这三项必须分别查看。`proof_status=incomplete` 是未完成证明，不应由“运行成功”或“校验零错误”掩盖。
