# 原理图自动化评审架构与代码导读

更新日期：2026-10-22。适用于当前 schematic-intake 单仓。本目录集中维护运行架构、源码职责、契约、提示词、工况图、运维及尚未完成的迁移事项。

当前系统由 Python 编排材料和报告，Node.js 调用本地 Codex CLI 进行对象评审，PyMuPDF 与 Pillow 叠绘工况图，HTML 与 Vue 提供两个展示入口。运行成功、契约通过、电气判定充分是不同状态。

## 阅读顺序

| 文档 | 解决的问题 |
|---|---|

| [数据与JSON契约](04-data-contracts.md) | 事实、分析、判定、图与展示分别保存在哪里 |
| [提示词与模型执行](05-prompts-and-execution.md) | 提示词拼接、自检、模型配置、续跑与修复 |
| [工况图生成](06-diagram-pipeline.md) | 路径声明、原图定位、方向、裁剪和图片缓存 |
| [运行与排障](07-operations.md) | 启动、定向评审、展示重建、校验与问题定位 |

本次“代码整理”是职责梳理与可更新源码索引，不移动运行源码，不修改电子判据，不重跑评审，不改变已发布报告。历史分析与当前设计文档有冲突时，以运行代码、检查条款和实际运行记录分别确定实现、判据与执行事实。

## 维护

在仓库根目录执行：

```powershell
py docs/architecture/tools/build_code_index.py
py docs/architecture/tools/check_docs.py
```

索引扫描生产源码、规则、提示词和相关工具，不扫描板卡材料、评审结果、node_modules、构建产物及历史归档。索引是静态结构导读，不是完整运行调用图。修改流水线时同步维护本目录对应文档；不能用修改文档替代实现。
