# 正式判定依据与主分析：basis-main.v1

主分析、分析思路、关系说明、图及计算直接引用同一份正式 decision_basis。候选排名不决定正式主展示；跨工况上界不伪装成同时可达的电流状态。当前仅通过板级 main_analysis_contracts.json 启用指定对象，未重跑或迁移其他对象。

## 生产路径

原始材料 → 独立分析/自检 → 正式卡的 decision_basis + main_analysis → 统一校验 → 同一依据的图规格 → detail.v2 → HTML / Vue。

`main_analysis` Schema：agent_review/schemas/main_analysis.v1.schema.json。basis_ref 固定 /decision_basis；state_index 同正式依据的计算项；kind 区分 operating_case / cross_case_bound / incomplete_proof。统一分析仍使用 analysis.v1 与结构化关键假设，不恢复两份前提/思路文案。

- 上界：proof_checks 列明 KCL、能量项、源范围、平均条件、器件参数适用性等本对象真正需要的证明义务；模型逐项给来源和状态。通过与不通过均要求决定性证明完成，不以“未发现反例”代替证明。
- 未完成：正式 decision_basis.kind=insufficient，说明必要 proof_gap。无需为了判待确认伪造物理超限反例；缺口仍须有明确的失败步骤、出处、原因和判定影响。内部可推导缺口继续处理，仅真实业务事实进入补料请求。
- 图只由 main_analysis.figure 持有，计算来自对应 states 项，不能另附一个未证实候选主图。上界图 kind=cross_case_relations，按模型实际推导给供能、储能、耗散和回流关系分组；默认不画箭头，说明非同时导通。节点无唯一电位时不填假电位。quantity_ref 引用正式上界或限额，控制器读取当前值。
- 前端与出图器共同使用正式引用；缺失、无效或与正式值不一致时不回退到候选或最大数字。既有未接入对象继续只读兼容，不能声称已完成新契约迁移。
- 图的元数据保存正式依据引用、计算项、依据源哈希及关系模式/箭头开关。发布校验拒绝旧图、不同依据的图或把关系图作为瞬时电流图。
- 新工作台、Schema、提示词及语义校验进入执行指纹；断点不跨契约复用。模型运行、原材料证据、计算和证明检查均留痕，禁止直接手改正式卡。

## 独立复核的边界

数学式的代数恒等和数值复算，仅证明在所列假设成立时的计算关系。源包络、半导体参数、被动性和有限储能等适用前提必须另有材料或完整推导支持。不能因为复算出旧数值就预设原通过结论，也不能把条件候选的成立条件混入另一份正式上界依据。
