---

## 1. 一句话

**发现问题先归类、再进对应层；Prompt 只收「跨拓扑、一句话能说清」的原则，不当问题垃圾桶。**  
能 L1（材料）解决的绝不进 L3（Prompt）；能 L2（契约字段）解决的不进长文自检。

---

## 2. 问题类（taxonomy，不是位号）

| 类 ID | 一类问题 | 典型表象 | 实例（说明用，勿写入 Prompt） |
|-------|----------|----------|------------------------------|
| **C1** | 包络未物理闭合 | 接口/任务书合法电压直接当应力 | SPDL 合法下限 → 功耗，缺「谁吸流」 |
| **C2** | 端压 ≠ 节点压 | 远端网压代对象两端 | 接口节点电压直接代电阻出口 |
| **C3** | 封装/路径与叙述不符 | 编造不存在的二极管腿或极性 | 共阴双管写成「脚 1–2→GND」 |
| **C4** | 取舍不可见 | 工程师默认「AI 漏项」；省略旁支无一句交代 | 未说明故障边界；或释放档只写 P=0、旁支平衡点只字不提 |
| **C4b** | 有条件上界说满 | 半幅/拓扑上界写成绝对最大值 | 「\|ΔV\|≲12 V → 1.44 mW」未写忽略了哪条支路 |
| **C5** | 假稳态 / 自洽口头化 | 方程有解但逻辑会拆 | 开漏截止 + 旁支口算却当长期稳态 |
| **C6** | 字段剧场 | 为过校验凑态/长链 | 强迫 formula≥N、堆未闭合态 |

一类问题可同时命中多层；**优先往更底层推**（材料 → 契约 → 自检/Prompt）。

---

## 3. 五层架构

```text
L5  回归 / 评阅归档     板级金样例、重评 md —— Agent 运行时不可见
L4  交付呈现             expert_review：主依据 / 前提 / 未计入
L3  判定 Agent           薄 Prompt + 通用自检轮 —— 只放跨类原则
L2  卡契约 / 校验        assumptions 闭合、取舍可见、轻量 validate
L1  工作台 / 材料        脚网、CA/CC、密封轨、手册摘录 —— 事实层
```

| 层 | 职责 | 放什么 | 不放什么 | 持续优化入口 |
|----|------|--------|----------|--------------|
| **L1** | 事实 | 邻居脚网、双管共阳/共阴、密封轨压、手册摘录 | 审图口诀、工况表、位号特判 | 新坑优先补工作台字段/抽取 |
| **L2** | 契约 | 主依据闭合写入 assumptions；未计入边界可见；校验只拦真缺 | 二极管脚序正则、器件名黑名单 | 加**结构化字段**优于加话术正则 |
| **L3** | 推理 | 判据一句话；C1/C2/C4/C5 级短原则；自检短问 | 位号/封装特判、few-shot 例文、场景清单 | 仅当原则已在 ≥2 板复现且一句话能写清才合入 Prompt |
| **L4** | 沟通 | HTML/报告展示主依据、前提、未计入 | 新物理规则 | 改 enrich / 报告模板 |
| **L5** | 防退步 | `agent_review/regression/*.json`、docs 重评归档 | 教模型怎么算 | 换板卸夹具；归档只作考卷 |

**C3（封装路径）主战场在 L1**：工作台写清共阳/共阴与各脚网络；L3 最多一句「路径须与封装拓扑一致，并写清吸收端是接口还是板内 GND」——**不写具体 MPN/脚号**。

## 4. 类 → 默认层（注册表）

| class | 默认层 | Prompt 是否允许 | 回归（L5） |
|-------|--------|-----------------|------------|
| C1 | L2 + L3 短句 | 是（闭合原则） | 可选：assumptions 含闭合语义 |
| C2 | L3 短句 | 是 | 可选 |
| C3 | **L1 优先** | 仅一句通用 | 板级路径叙述抽查 |
| C4 / C4b | L2 + L3 短句 + L4 | 是（旁支一句 + 上界带条件） | 可选抽查 |
| C5 | L3 自检 | 是 | 已有如 R14 板级坑 |
| C6 | L2 validate | 否（宜减规则） | — |

仓库内实现提示：

- Prompt / 自检：`agent_review/prompts/judge/*.md`、`_p11_self_check.md`、`_common_judge.md`
- 工作台：`agent_review/workbench.py`
- 校验：`agent_review/validate_job.py`
- 回归：`agent_review/regression/`、`python -m agent_review.regression_check`
- 技能说明：`.cursor/skills/agent-review/SKILL.md`

## 5. 持续优化流水线

```text
踩坑 / 重评归档
  → 归入 C1…C6（本文件 §2）
  → 选层：能 L1 不进 L3；能 L2 字段不进 Prompt 长文
  → 改对应层 +（可选）L5 金样例
  → 重跑相关对象 → 对照归档/金样例
  → 若 Prompt 行数暴涨或出现器件/位号专名 → 设计异味，打回拆层
```

### Prompt 准入门禁（合入前自问）

1. 是否已用一句话跨拓扑说清？（否 → 不进 Prompt，改 L1/L2）  
2. 是否至少两个板或两类拓扑会踩？（否 → 先 L5/材料，观察）  
3. 是否可用结构化字段代替散文约束？（是 → 优先 L2）  
4. 是否点名了位号、MPN、脚序？（是 → **禁止**进 Prompt）

### 允许 / 禁止进 Prompt

| 允许 | 禁止 |
|------|------|
| 包络须落到钉电位与灌拉 | SPDL / 48 mA / 某脚 1–2 |
| 端压 ≠ 远端节点 | 齐纳 Vf/Zzt 公式表 |
| 路径与封装拓扑一致；写清吸收端 | R4/R14 例文 few-shot |
| 取舍须可见；宁少勿凑态 | 按器件类型的工况清单 |

## 6. 与现行 Judge 的关系

深审白名单（`rules/agent_rule_ids.json`）：**P11-A01/A03/A07、P12-A01、P12-A03…A07**。  
程序路径（不深审）：**P12-A02**（与 P21-A01 同算法）、**P21-A01** 等。

同会话默认三轮：

1. 分析 `.analysis.md`（L3：停手=写透）  
2. 自检：规则专用 / `_p11_self_check.md`（A01/A03）/ `_deep_self_check.md`  
3. 落卡 JSON（L2：结论=分析汇总）

难例可选：`--critique` / `_p11_critique.md`（再追问一轮 → 同步 JSON）。  

编排：`agent_review/orchestrator.mjs`（`analyze_selfcheck_card` / `critique`）。  
呈现与门禁：L4 `expert_review.html`、L5 可选 `regression_check`。

## 7. 效果对齐（不加模块 · 已落地）

相对「简单 Prompt 对话审图」，差距在任务形态（交卷 vs 算通），不在材料是否够全。约定与入口：

1. **停手标准**：分析/自检 Prompt 以写透为准；JSON 为汇总。  
2. **难例续聊**：`python -m agent_review.run_p11a01_objects --board … --objects R14 --critique`（须已有 `.analysis.md`）。  
3. **接受批跑上限**：全量稳定对齐对话过程分不现实；要对齐就用少对象 + 可追问。  
4. **不加**新工作台字段、报告置顶分析模块、process_expect 扩面——现有材料已够工程师用。
