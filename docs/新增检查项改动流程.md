# 新增检查项 · 全流程改动说明（归档）

| 项 | 内容 |
|----|------|
| 用途 | 新增一条产品中心 check 时，按本文从业务确认 → 配置 → 程序/Agent → 材料 → 工况图 → 报告 → 验收 |
| 配套 | 交付踩坑清单见 `docs/新增检查项交付检查清单.md`；P11 质量分层见 `docs/P11质量分层架构.md` |
| 入口 | 材料 `python -m kernel.run`；判定 `python -m agent_review.run`；查看 `python -m agent_review.serve` |
| 日期 | 2026-10-19 |
| 原则 | **能材料层解决的不进 Prompt；能程序闭合的不进 Agent 白名单；禁止手改 `verdicts.json` / `context_store/**` / `agent_jobs/**`；禁止把某板某位号拓扑写进 Prompt** |

---

## 0. 一句话总览

```text
业务确认（本文件 §1）
    ↓
登记进产品中心配置（§2）
    ↓
选定路径：程序自评 / Agent 深审 / 混合（§3）
    ↓
按路径改代码与 Prompt（§4–§6）
    ↓
额定字段 / 任务书门禁 / 枚举对象（§7–§8）
    ↓
（可选）工况通路图（§9）
    ↓
报告与门禁（§10）
    ↓
单板验收 + 踩坑清单自检（§11）
```

当前流水线阶段（`agent_review.run`）：

```text
prep → enumerate → program → cases → calc → context_build → judge → stress_figures → aggregate → gate
```

- **program**：白名单外的项，调 `schematic-review` 的 `kernel.checkers`
- **judge**：`rules/agent_rule_ids.json` 内的项，走 Cursor SDK（`orchestrator.mjs`）
- **cases / calc**：主要为 P11 拆工况与 `program_stress`（Agent 项旁证）
- **stress_figures**：仅 `FIGURE_RULES` 内规则生成工况通路图
- **aggregate / gate**：写 `verdicts.json`、`evidence/*.json`、`report_data.json`；门禁不要求 `expert_review.html`

## 1. 需要你（产品/电气）先确认的点

未确认前不要改代码。下列每一项都要有明确结论（可写在 PR / 会话备忘里）。

### 1.1 规则身份

| # | 确认项 | 说明 | 落点影响 |
|---|--------|------|----------|
| A1 | **规则 ID** | 如 `P12-A08`，与源表 `docs/原理图评审_85项_0916.xlsx` 一致 | 所有配置文件主键 |
| A2 | **中文名称 / 严重度 / 大类** | 报告侧栏、列表、标题用 | `product_center_15.json`、`xlsx_detail_15.json` |
| A3 | **是否在本期产品中心子集** | 本期约 25 项；85 表里很多项本期不做 | 不进 `rule_ids[]` 则流水线不跑 |

### 1.2 判定语义（最重要）

| # | 确认项 | 说明 |
|---|--------|------|
| B1 | **判据一句话** | 比什么、阈值多少（如「\(P_{max} ≤ 0.5 × P_{rated}\)」） |
| B2 | **四个结论各自何时用** | `是` / `否` / `待确认` / `不适用` 的边界；缺资料是待确认还是不适用 |
| B3 | **「是」必须有哪些可核验出处** | 手册页 / 立创 URL / 任务书字段；禁止口头数升绿 |
| B4 | **禁止的作弊路径** | 如禁止 `0.7×VCC`、禁止用 Irms 冒充 Isat（写进 notes + Prompt） |
| B5 | **整项不适用的前置条件** | 如「无 Tamb → 整项 NA」「无连接器整机需求 → NA」 |

### 1.3 对象与材料

| # | 确认项 | 说明 |
|---|--------|------|
| C1 | **检查对象粒度** | 器件位号 / 网络 / 端口 / 整板一次 |
| C2 | **对象筛选规则** | 例：装配电阻、多 IC 信号网、MOSFET、航插 CN/J… |
| C3 | **必需材料** | BOM、网表、原理图 PDF、规格书、任务书哪些字段 |
| C4 | **额定（规格书）vs 应力（工况）** | 哪些字段走抽参瀑布；哪些是板上算出来的 \(V_{max}/P_{max}/I_{peak}\) |
| C5 | **关联图幅范围** | `device` / `net` / `nets` / `peer_caps` / `path`（报告里跟哪些页） |

### 1.4 实现路径（二选一或混合）

| # | 确认项 | 推荐默认 |
|---|--------|----------|
| D1 | **程序可闭合？** | 规则可写成确定性比较（位号重复、标注可解析、BOM 一致）→ **程序自评** |
| D2 | **必须读图/取舍？** | 应力路径、最坏态取舍、接口包络 → **Agent 深审** |
| D3 | **混合？** | 程序先拆工况/旁证，Agent 终判（当前 P11-A01/A03 模式） |
| D4 | **是否要工况通路图** | 默认仅器件选型应力类需要；会进 `FIGURE_RULES` |

### 1.5 交付与验收板

| # | 确认项 | 说明 |
|---|--------|------|
| E1 | **验收板** | 至少一块真实板（如 `boards/0918全量`）上能看到是/否/待确认/不适用样例 |
| E2 | **金样例（可选）** | 1～2 个对象的期望结论，写入 `agent_review/regression/*.json` |
| E3 | **报告形态** | 当前主交付是 `report_ui` 读 JSON；旧 `expert_review.html` 仍可对照，但流水线不再以生成 HTML 为门禁 |

## 2. 配置层改动（两条路径都要做）

下列文件在 `schematic-intake`（除非注明）。

### 2.1 必改：产品中心清单

**文件**：`rules/product_center_15.json`

| 字段 | 动作 |
|------|------|
| `rule_ids[]` | **追加**本项 ID（顺序影响列表展示，通常按大类） |
| `notes.<rule_id>` | 写清判据要点与禁止作弊句（给实现者/报告 notes） |
| `agent_groups_by_category` | 归入合适 `agent_id` 组；新技能域可新建一组 |
| `needs_dc_modes` | 仅当本项要跑直流工况分析器时加入（现仅 P11-A01/A03） |
| `items[]`（若有） | 补 `rule_id/name/severity/category` 元数据（`enumerate.rule_meta_map` 会读） |

### 2.2 必改：源表细节与检查流程文案

| 文件 | 动作 |
|------|------|
| `rules/xlsx_detail_15.json` | 从 85 项 xlsx「规则详情」同步一条：`name`、`severity`、`check_steps`、`rule_detail.*` |
| `rules/intent_steps_15.json` | 补本项的业务意图步骤、`sheet_scope`、配方/门禁相关说明（报告「推导步骤」会读） |

`xlsx_detail` 是展示与 playbook 文案源；`intent_steps` 是「这项在查什么」的流程叙述。两者 ID 必须与 `rule_ids` 一致。

### 2.3 按路径：Agent 白名单

**文件**：`rules/agent_rule_ids.json`

- 走 **Agent 深审** → 把 ID 加进 `agent_rule_ids[]`
- 走 **纯程序** → **不要**加入；未在白名单内的项一律 `program_stage` 处理
- 改白名单后：对应 Prompt 必须有 `agent_review/prompts/judge/<ID>.md`；三轮深审还须 `<ID>.analysis.md`

同步注意：`agent_review/rule_modes.py` 里 `_DEFAULT_AGENT` 是白名单文件缺失时的兜底，长期应以 JSON 为准；若改了默认集合，两边保持一致。

### 2.4 按对象类型：枚举网络规则

**文件**：`agent_review/rule_modes.py` 中 `_NET_RULES`

若检查对象是**网络名**而不是器件位号（如 P04、P21、P12-A02），必须加入 `_NET_RULES`，否则上下文规划会把对象当器件去找 MPN。

## 3. 路径分流（读代码时的对照）

| 路径 | 触发条件 | 终判写在哪 | 主要代码 |
|------|----------|------------|----------|
| 程序自评 | ID ∉ `agent_rule_ids.json` | `program_candidate.json` → 同步为 `agent_jobs/<rid>/<obj>.json` | `program_bridge.run_program_checkers` → `schematic-review/kernel/checkers/all15.py` |
| Agent 深审 | ID ∈ 白名单 | SDK 落 `agent_jobs/<rid>/<obj>.json` | `stages/judge.py` → `orchestrator.mjs` |
| 混合（P11） | 白名单 + cases/calc | Agent 终判；`program_stress` 仅旁证 | `p11_pipeline` + Prompt 禁抄程序数 |
| 整项不适用 | `enumerate` 门禁清空对象并写 `rule_na_reasons` | aggregate 落项级 NA | `enumerate.apply_rule_precondition_gates` |

`split_rule_ids()`：`program = 全部 rule_ids − agent 集合`。

## 4. 程序自评路径 · 改动清单

依赖仓：`schematic-review`（与 intake 同级，或 `SCHEMATIC_REVIEW_ROOT`）。

### 4.1 检查函数

**文件**：`schematic-review/kernel/checkers/all15.py`（或拆到 `extra4.py` 再挂上）

1. 在 `TITLES` 增加中文标题  
2. 实现 `check_<snake>(kg) -> CheckResult`  
3. 挂到文件末尾 `REGISTRY["Pxx-Ayy"] = _wrap(check_...)`  
4. 输出必须能被 `program_bridge.program_card_to_judge_card` 吃下：  
   - `object_cards[]`：`object`、`verdict_zh`、`summary`/`conclusion`、`phenomenon`、`calc`、`stuck`、`evidence_refs`、`steps`/`solution`（有则更好）  
   - 项级 `verdict_zh`：是/否/待确认/不适用（或 INSUFFICIENT → 桥接层会收成待确认）

### 4.2 对象枚举（intake）

**文件**：`agent_review/enumerate.py`

1. 在 `ENUMERATORS` 增加 ` "Pxx-Ayy": lambda kg: ...`  
2. 若需「无任务书字段则整项 NA」，扩展 `apply_rule_precondition_gates`（参考 P12-A03 Tamb、P12-A07 连接器需求）  
3. 若对象是网：同时改 `enumerate_board` 里把该 ID 划入 `net_keys` 的分支（与 `_NET_RULES` 一致）

没有枚举器时：`by_rule[rid] = []`，门禁可能因「无卡」或「整项空对象」表现为不适用/缺卡，**不要依赖这个当正式 NA**。

### 4.3 程序桥

一般**不用改** `program_bridge.py`：它按 `program_rule_ids` 批量调 `REGISTRY`。  
若新卡字段特殊，再扩 `program_card_to_judge_card` 映射。

### 4.4 报告整改建议（可选）

旧 HTML 生成器里有按 rule 的 advice 函数（`build_expert_html._advice_*`）。  
若仍对照 `expert_review.html`：可补一条；主交付 `report_ui` 尚未复刻该段时，可记为后续前端工作，**不阻塞程序项上线**。

## 5. Agent 深审路径 · 改动清单

### 5.1 Prompt 文件（intake）

目录：`agent_review/prompts/judge/`

| 文件 | 何时必须 | 内容 |
|------|----------|------|
| `<ID>.md` | 白名单必有 | 落卡轮：判据、落卡字段、禁止项 |
| `<ID>.analysis.md` | 三轮深审必有 | 分析轮：如何读工作台、如何取舍 |
| `<ID>.self_check.md` | 可选 | 规则专属自检；否则用 `_deep_self_check.md` / `_p11_self_check.md` |
| `_common_judge.md` | 已有 | 公共落卡契约；勿塞个案拓扑 |

另有：`prompts/_common_judge.md`、`prompts/judge/_deep_self_check.md`。

**Prompt 禁令（必须遵守）**：

- 不写某板某位号、某条网的拓扑特判  
- 不把「凑够 N 个态」当目标；宁少勿凑态  
- `program_reference` / `program_stress` 只作旁证，禁止抄数字与态名当结论  

### 5.2 工作台材料

**文件**：`agent_review/workbench.py`（及 context 构建）

深审前 `context_build` 会为对象准备切片。新项若需额外字段（脚网、密封轨、手册摘录）：

- 优先在 **材料层 / board_kg / pintable** 备好（L1）  
- 再在 workbench 组装进对象上下文  
- 不要靠 Prompt 让模型猜脚序  

### 5.3 校验

**文件**：`agent_review/validate_job.py`

若新项有强制字段（如 `headline_zh`、`electrical.P_rated`），在 `validate_judge_card` 增加规则级校验；门禁 `delivery_gate` 会对每张 `agent_jobs` 卡跑校验。

### 5.4 编排

通常**不用改** `orchestrator.mjs`：它按枚举里的 Agent 任务调 SDK。  
确认本机有 Node ≥ 22.13、`CURSOR_API_KEY` 或已 login，根目录与 `sdk/` 已 `npm install`。

### 5.5 单测式试跑

```bat
cd K:\project\schematic-intake
set PYTHONPATH=%CD%
python -m agent_review.run --board boards\<板> --rule-ids Pxx-Ayy
```

难例续聊（若实现了类似 P11 的入口）：`--critique` 或专用 `run_*_objects`。

## 6. 混合路径（程序旁证 + Agent 终判）

仅当确认 D3=混合时采用。当前样板：**P11-A01 / P11-A03**。

| 步骤 | 模块 | 说明 |
|------|------|------|
| 拆工况 | `p11_pipeline` / `cases_stage` → subprocess `schematic-review` `situations` | 写出 `operating_cases/` |
| 逐态计算 | `calc_stage` → `program_stress/` | 旁证数 |
| 深审 | `judge` + Prompt | 明示禁止抄 `program_stress` |
| 卡 enrichment | `p11_card_enrich.py` | 把 figure / 公式 UI 挂到 `solution.states` |

新混合项往往要：

1. 扩展或分叉 `p11_pipeline`（勿把无关规则硬塞进 P11 专用命名）  
2. `stages/judge.py` 里 `_P11_STRESS` 一类集合是否纳入  
3. Prompt 中写清「程序包角色」  

工作量显著大于纯程序或纯 Agent，**需在 §1 明确批准**。

## 7. 材料层 · 额定与抽参

**何时要做**：判据依赖规格书额定（功率、耐压、Isat、Vds、I_rated…）。

| 步骤 | 文件 | 动作 |
|------|------|------|
| 登记字段 | `kernel/rated_registry.py` → `RULE_RATED` | `comp_types`、`fields[].field`、`strategies`（hard/mpn_code/agent）、`stress_fields` |
| 类型默认 | 同文件 `TYPE_FIELDS` | 新器件类型要抽的默认字段 |
| 抽取实现 | `kernel/rated_hunt.py` / `rated_fields.py` | 新字段的 PDF/立创/码表逻辑；`field_present` 必须认识新字段 |
| Agent 查参 | `mpn_param` / `mpn_vr` + prompts | 硬路径空时的兜底 schema |
| 规格书下载 | `kernel/steps/s2_datasheet.py` | 是否为新类型打开 fetch（如被动件开关） |
| 跑材料 | `python -m kernel.run --board ... --from-step 2` | **不跑深审**；勿随便设 `RATED_HUNT_SKIP_AGENT=1` |

**应力字段**（\(V_{max}\) 等）标在 `stress_fields`，**不要**指望抽参瀑布填应力。

细节踩坑表：见 `docs/新增检查项交付检查清单.md` §2。

## 8. 对象枚举与任务书门禁（再强调）

| 场景 | 做法 |
|------|------|
| 无此类器件 | 枚举为空 → 项级「不适用」或「无对象」；在 notes/报告写清 |
| 有器件但缺任务书包络 | **门禁清空对象 + `rule_na_reasons`**，避免上百张「待确认」刷屏（P12-A03/A07 模式） |
| 网络项 | `_NET_RULES` + enumerate 的 net 分支 + 枚举器返回网名 |

## 9. 工况通路图（可选）

**模块**：`agent_review/stress_figures.py`（`FIGURE_RULES`）、`stress_snap.py`、`stress_path_render.py`

| 确认 | 动作 |
|------|------|
| 本项要出图 | 把 ID 加入 `FIGURE_RULES` |
| 图挂在哪 | Agent 卡 `solution.states[].figure` / `figure_pages`（P11 经 `p11_card_enrich.lookup`） |

阶段顺序：`judge` 之后、`aggregate` 之前。出图不耗 SDK token。

## 10. 汇总、门禁、报告

### 10.1 汇总

**文件**：`agent_review/aggregate.py`、`expert_report.normalize_evidence`、`report.py`

- 按 `method = agent_judge | program` 汇总  
- 写出 `verdicts.json`、`evidence/<ID>.json`、`report_data.json`  
- 展示层洗路径：`kernel/report_text.py`、`expert_report._humanize_card_copy`  

### 10.2 门禁

**文件**：`agent_review/delivery_gate.py` → `agent_review_gate.json`

检查大致包括：

1. 无 `gate_failed.json`  
2. Agent 项：上下文仓密封（无 Agent 项则跳过）  
3. 枚举出的每个对象都有合法 `agent_jobs` 卡  
4. 存在 `evidence/*.json` 与 `report_data.json`  

**不再**要求 `expert_review.html`。

### 10.3 报告 UI

| 形态 | 状态 |
|------|------|
| `report_ui` | 现行主交付；读 JSON；专家报告细节仍在复刻中 |
| `expert_review.html` | 旧生成器 `schematic-review/vendor/expert_html/build_expert_html.py`；可对照，**不要**把 serve 根路由永久指回该文件 |

新项上线最低要求：`evidence/<ID>.json` 里对象卡字段齐全，serve 下能打开并看懂结论。  
若依赖旧 HTML 的 advice / 图幅 PDF.js：对照 `intent_steps.sheet_scope` 与 workbench 页码是否齐。

### 10.4 回归（推荐）

`agent_review/regression/*.json` + `python -m agent_review.regression_check`  
放入「对象 + 期望结论关键词」，防止 Prompt/抽参回退。

## 13. 常见错误（新增项时）

1. **只加了 Prompt 没加 `product_center_15.json` 的 `rule_ids`** → 流水线根本不枚举  
2. **进了白名单但没有 `.analysis.md`** → 三轮深审不完整或失败  
3. **程序项却写入白名单** → 程序结果被忽略，空耗 SDK  
4. **网络项未进 `_NET_RULES`** → 上下文按器件找 MPN，材料错乱  
5. **枚举器缺失** → 静默空对象  
6. **额定字段未进 `field_present`** → 反复 HUNT、报告空抽出  
7. **缺任务书却不设门禁** → 上百张待确认  
8. **手改 `verdicts` / `agent_jobs` 充数** → 门禁与复跑不一致，禁止  
9. **把验收板拓扑写进 Prompt** → 换板即失效，且违反分层架构  
10. **以为要生成 `expert_review.html` 才算交付** → 现以 JSON + `report_ui`/`serve` 为准

## 14. 验收命令模板

```bat
cd K:\project\schematic-intake
set PYTHONPATH=%CD%

REM 材料（需要额定/规格书时）
python -m kernel.run --board boards\<板> --from-step 2

REM 只跑本项
python -m agent_review.run --board boards\<板> --rule-ids Pxx-Ayy

REM 看门禁
type boards\<板>\review_out\agent_review_gate.json

REM 打开报告
python -m agent_review.serve --board boards\<板>
```

验收时打开本项，至少核：

1. 项级结论与对象表一致  
2. 是/否有出处；待确认能看见卡点；不适用有原因  
3. 对人文案无 `review_out/`、`context.json`、`board_kg` 等系统路径  
4. （若有图）工况图能打开且跨页可理解
