## 2. 额定参数抽取（材料层）

定额字段与工况应力分开：**额定**走抽参瀑布，**\(V_{max}\)/\(P_{max}\)/\(I_{peak}\)** 走网表/任务书/深审。

### 2.1 共用瀑布（允许每 check 不同抽取器）

```text
硬出处：手册 PDF → 立创商品参数 → 联网页（可密封）
    ↓ 空
线索层：料号编码等（默认不密封、不升绿）
    ↓ 空
Agent 查参：value + cite + confidence（仅 high+cite 可密封）
```

登记处：`kernel/rated_registry.py`（`RULE_RATED` / `TYPE_FIELDS`）。  
电容 Vr 专用：`apply_capacitor_vr`；其它字段：`apply_rated_fields` + `hunt_rated`；Agent：`mpn_vr` / `mpn_param`。

### 2.2 曾踩坑（抽参）

| 曾踩坑 | 表象 | 修复要点 | 新增时自检 |
|--------|------|----------|------------|
| 只要正则/料号码、报告抽不出 | 豆包能答 50V，我们空 | 硬路径 + 码线索分层展示；勿把线索当密封升绿 | 缺手册时抽出区有「线索」标签；总判仍可待确认 |
| 写死某颗 50V | 换料号错/解不出 | 通用码表 + 正则；解不出就空 | 换 Murata/Samsung 等应 MISS 码层，走硬路径/Agent |
| 码面 `500` 被抽成 500V | 错密封 | `_reject_voltage_code_as_volts` | 含三位电压码的 MLCC 勿出现 Vr=码面数字 |
| 错档 PDF / 无出处旧值钉死 | 6.3V 挡住立创 50V | 弱密封可被硬出处覆盖 | 有立创/正本时，以硬出处为准并带 URL/引文 |
| `field_present` 不认新字段 | 已写入却反复 HUNT / 仍缺 | `rated_fields.field_present` 把新 params 字段列入 | 新字段写入后 `field_present` 为真 |
| 电流类立创参数抽不到 | `named_param` 误跳过「电流」行 | 电压/电流字段分支跳过规则 | TVS Ipp、连接器额定电流等能从立创命中时可见 |
| 所有 check 共用一个 Vr 正则 | 功率/Vds/Isat 罩不住 | **允许不同 check 不同抽取逻辑**；只复用瀑布骨架 | 新字段有专属立创名/PDF 片段/Agent schema |
| PDF 有、params 空 | `datasheet_miss` 全 hit 但密封仍空 | 重跑 s3 抽参 + s5 `apply_rated_fields`；电阻靠系列表/立创功率 | 抽检 `pintable.params` 非空或 HUNT 有 lcsc/datasheet |
| 连接器被 fetch skip | CN/H 无 PDF、无 I_rated | 勿把 DB/PH2.0 等打进 `should_skip`；hunt 含 CN/H | P12-A07 对象有手册或立创电流 |
| 温区抽不到 | 独立行 `-55℃~+125℃` / EIA X7R | `TOP_RANGE`+裸行；介质码 `eia_dielectric`；立创「工作结温」 | P12-A03 器件侧 T_op 有值（任务书 Tamb 另算） |
| P12-A03 缺 Tamb 却 12×待确认 | 任务书无环境温度 → 整项不适用 | `enumerate`：`apply_p12a03_tamb_gate`；有源含 diode | 无 Tamb 不开对象深审；报告一项「不适用」 |
| P12-A03 漏二极管 | 有源含 D* | `_actives` 含 `diode`/`tvs` | 枚举含 D2–D10 等 |
| P12-A07 缺整机需求却待确认 | 任务书无电流/插拔/防护需求 → 不适用 | `design_task_has_connector_machine_reqs` 门禁 | 整项 NA + 短概括 |
| 检查项头只有计数 | KPI 下加一句话原因 | `rule_summary` → evidence → `.rule-summary` | 不用点开逐对象 |
| TVS/MOS 字段摊到所有 D/Q | 信号管也缺 Vrwm/Vds | `wanted_fields` 勿把非 `*` 规则字段全并入 | 4148 类只追 Vf/温区，不追 TVS |
| 稳压器追 VOH/VCC | L78L 缺逻辑电平 | 稳压器用 VI/VO，去掉 IO/通用 VCC | Ux 稳压项只见输入/输出窗 |

材料层只跑规格书 / 抽参（**不跑深审**）：

```bat
set PYTHONPATH=%CD%
python -m kernel.run --board boards\<板> --from-step 2
```

- 硬路径空时会走 **Agent 查参兜底**（`mpn_param`）——这是材料步骤，不是深审。
- **不要**设 `RATED_HUNT_SKIP_AGENT=1`（那会关掉查参兜底；仅本地调试硬路径时才用）。

### 2.3 冲突与升绿

- [ ] 手册/立创 vs 料号码 vs Agent 不一致 → 标「存疑」，**不自动升绿**
- [ ] 「是」必须有可核验 cite（手册页/立创 URL/命名规则）；口头数只进线索
- [ ] Agent：`confidence=low` 或无 cite → 仅线索

## 5. 建议抽检脚本（新增后 10 分钟）

```bat
cd K:\project\schematic-intake
set PYTHONPATH=%CD%
python -m agent_review.run --board boards\<板> --rule-ids <本项>
python -m agent_review.serve --board boards\<板>
```

在浏览器对象详情中确认：

1. 摘要 / 未闭合 / 公式来源列 / 审图依据 —— 无系统路径、无整段重复  
2. 规格书抽出字段与检查项匹配  
3. 总判待确认时，能看见卡点（黄条或摘要）  
4. 额定有值时带来源；冲突时有存疑、未误升绿  

可选：在 `evidence/*.json` 的 stuck/summary 上搜 `context.json|board_kg|review_out/`（展示层应已洗掉；原始 agent_jobs 可仍有，属内部）。
