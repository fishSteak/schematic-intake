# 统一评审详情展示

本次只统一展示及文案整理，不重新进行电子判定、不迁移旧判定卡、不改变原始数值或外层整改建议。当前源报告包含 250 条具体对象记录及 10 条无适用对象占位记录，全部保留。

## 数据流

`verdicts.json 的 object_cards → detail_prose（按需模型整理）→ detail_view.build → evidence/<检查项>.json 的 review_detail → HTML / Vue`

`report_data.json.review_details` 同步相同视图，原始判定卡不添加展示字段。`kernel/report_workbench.py` 只补资源定位，前端不按最大数字选择主工况、不从公式截取前提、不把比较理由替代分析思路。

展示版本是 `detail.v2`，独立于原始 `review.v1`；机器可验证契约位于 `agent_review/schemas/review_detail.v2.schema.json`。模块定义在 `report_ui/src/review-modules.json`，共享 CSS 在 `report_ui/src/review-detail.css`。材料参数与分析思路分别展示；成立条件和具体因果关系融合进同一份分析文案，关键假设仅在审计区展开追溯；判定要点使用原记录的结果字段、限额或条件核查，不强制功率指标。主工况引用由原卡明确角色或模型从既有分析中提取，没有明确依据时不猜选。其他工况仅显示原有文本及数值。

不适用对象不展示计算、极值或工况。未单列的前提、覆盖范围、图幅等显示明确状态，不能填入通用推理。规格书缓存摘录单独标为参考，不覆盖评审采用值。

## 文案来源与断点

`agent_review/detail_prose.py` 使用 `gpt-6.1-sol`、最多两个 CLI 会话并行，批量整理旧卡。模型只读显式提供的原卡及对应分析快照，不重新查证或计算。提示词位于 `agent_review/prompts/judge/detail_prose_v2.md`，不含板级答案。

产物位于 `review_out/detail_prose/<检查项>/<对象>.json`，包含统一分析步骤及其假设引用、主工况引用、通路说明、原文引用以及 ready / source_insufficient / source_conflict 状态。来源缺失或矛盾只记待复审，不改变正式判定或自动启动深审。

每条产物保存源卡及分析哈希、契约哈希、输出哈希、真实 CLI run_id 和批输出位置；展示前还核对真实 completed run、原批输出及原上下文，不能只凭侧车声明已由模型生成。批次上下文、schema、运行结果和校验记录保存在 runs 目录。源结果、分析或文案契约变化才补生成；CSS 和布局变化只重建页面。原生新契约的合规文案直接复用。

## 正常发布

已有报告可通过 `py -m agent_review.publish_details --board boards/<板>` 完成补生成及正常发布；该命令不运行电子评审。启用统一展示后，正常报告生成入口 `write_expert_deliverables` 也会先检查文案缓存，再同步数据并构建 HTML。

正常发布先从已完成批次逐条恢复符合当前源、提示词及校验的模型原文，只重跑未通过条目；不修改原批输出或伪造运行记录。文案生成失败时不开始发布；构建失败则恢复此前 evidence、report_data 和两个 HTML。发布回执保存对象数、原始判定卡不变检查及文案状态计数。前端缺少展示数据时显示明确状态，不回退到旧的猜选逻辑。

## 验证

定向测试覆盖未知值不变零、主工况歧义不猜选、条件检查无功率框、不适用隐藏工况、文案引用校验、输入不可变、共享模块定义以及发布失败恢复。另执行全源记录适配、HTML 脚本语法检查、Vue 构建和代表性详情/PDF 浏览检查。


## 2026-10-21：成立前提与判断思路合并

展示契约升级 detail.v2，分析字段统一为 analysis.v1：

- `analysis_steps: [{text, assumption_refs}]`：至多三步，业务仅展示这一份分析；条件和具体因果自然融合，不堆参数或计算结果。
- `key_assumptions`：稳定 ID、原文、supported / model_assumption / unresolved / recorded 状态及来源定位；原生 review.v1 的 premises 保持完整，工况 premise_refs 和证据引用继续生效。recorded 仅表示旧记录已有，不被程序升级为已证明。
- `analysis_origin / analysis_provenance`：区分原生新模型输出、合并模型输出与无独立假设的旧模型原文复用，均保留原始运行和输出哈希，不伪装全部重新生成。
- 原生深审新输出使用 `analysis_contract=analysis.v1` 和 `analysis_steps[{text,premise_refs}]`，不再输出 reasoning_steps；premises 为审计结构，不作为第二份展示文案。新工作台强制新字段，历史卡继续只读兼容。
- 旧式 Agent 新输出同样使用 analysis.v1、analysis_steps 和 key_assumptions，不再同时输出 assumptions/reasoning_steps。支持事实需要实际出处，未知引用、遗漏必要假设或抹除条件性会被校验拒绝。

本轮旧卡已有独立假设的 12 条由模型重新整合；其余 248 条无独立假设且源内容不变，保留实际原模型文案，仅迁移结构。旧文案的兼容复用须同时核对冻结的 v1 提示词、Schema、原始来源和真实 completed CLI 输出；有独立假设或源内容变化时不可走此路径。原始评审卡、判定与计算数值不修改。后续新契约已提供合规分析时直接使用，不另开一轮重复文案生成。

前端只读取 analysis_steps，不拼接 premises/reasoning_steps；假设在“判定证据与未解边界 → 关键假设与来源”展开，工况独有且影响有效性的条件仍贴近主工况标明。CSS/标题变更不触发电子重审；新工作台、Schema、通用分析校验和提示词进入执行指纹，旧断点不会冒充新契约完成结果。
